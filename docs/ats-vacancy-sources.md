# ATS-источники вакансий и предложение по реестру источников

**Исследование 24–25 сентября 2026 года.** Исторический обзор и проект
архитектуры: сам по себе он не добавлял адаптер, миграцию, запуск импорта,
frontend или Production-разрешение. Позднее отдельный ограниченный
[Greenhouse POC](/docs/greenhouse-poc) был реализован; его фактические границы
описаны там.

## 1. Вывод и границы исследования

Доски ATS работодателей позволяют реализовать один адаптер и подключать
разрешённые компании через конфигурацию. Они **не** дают автоматически
доступный и юридически свободный каталог Казахстана. Первый предлагаемый
адаптер — **Greenhouse**, второй — **Lever** при наличии прав конкретных
работодателей. У обоих документированы публичные способы получения,
идентификаторы вакансий и сбор доски; найдены примеры найма в Казахстане.
Workday отложен из-за отсутствия подтверждённого официального анонимного
контракта CXS. Партнёрский feed Ashby интересен для отдельного соглашения.

Другие технические кандидаты: SmartRecruiters, Workable, Recruitee,
Teamtailor, Personio. Recruitee и Teamtailor требуют ключ работодателя;
условия анонимного доступа SmartRecruiters нужно уточнять. BambooHR ATS
требует разрешённого доступа и не доказывает полный публичный feed.
Ни один источник не получил Production-разрешение только по этому обзору.

Основной контекст: [стратегия](/docs/vacancy-supply-2026) и
[архитектура импорта](/docs/vacancy-supply-architecture). Официальная
документация разработчиков, поддержки и условий — главный источник.
Страницы работодателей дают лишь свидетельство возможной географической
релевантности: индекс поиска может сохранять закрытые вакансии. API
провайдеров не вызывались, квоты не расходовались, открытый код GitHub
читался, но не запускался. «Неизвестно» значит отсутствие доказательства,
а не отсутствие функции у ATS.

## 2. Сравнение ATS

Независимые категории доступа: **A** — документирован анонимный GET,
но не лицензия на повторное распространение; **B** — документировано
использование для карьерного сайта работодателя; **C** — партнёрский
канал с явным согласием работодателя; **D** — права JobHub на хранение,
показ и коммерческое применение не подтверждены. Эти буквы не совпадают
с приоритетами общей стратегии.

Все URL ниже используют HTTPS. `{board}`, `{site}`, `{company}`, `{tenant}`
и `{id}` — непрозрачные ID; их нельзя угадывать по видимому названию компании.

| ATS и документация | Доступ и ID клиента | Список / детали | Пагинация |
| --- | --- | --- | --- |
| [Greenhouse](https://docs.greenhouse.io/job-board.html) | Публичный GET без ключа; board token; A/B/D | `boards-api.greenhouse.io/v1/boards/{board}/jobs?content=true`, деталь `/{id}` | Пагинация не описана; список и `meta.total` |
| [Lever](https://github.com/lever/postings-api) | Публичный GET без ключа; site slug и регион; A/B/D | `api.lever.co/v0/postings/{site}?mode=json`; для EU `api.eu.lever.co` | `skip`, `limit` |
| [Workday](https://community-content.workday.com/en-us/public/products/platform-and-product-extensions/soap-api-reference.html) | Корпоративная авторизованная интеграция; tenant/host/site; D | Официальные Recruiting services или разрешённый экспорт; общего анонимного URL не подтверждено | По договору |
| [Ashby](https://developers.ashbyhq.com/docs/public-job-posting-api) | Публичная доска без ключа; имя board с учётом регистра; A/B/D, отдельно C | `api.ashbyhq.com/posting-api/job-board/{board}?includeCompensation=true`; описание в списке | Не описана |
| [SmartRecruiters](https://developers.smartrecruiters.com/docs/endpoints) | Компания как tenant; примеры без auth, новая документация упоминает ключ/OAuth; B/D, A условно, C отдельно | `api.smartrecruiters.com/v1/companies/{company}/postings`, деталь `/{id}` | `offset`, `limit`, `totalFound` |
| [Workable](https://help.workable.com/hc/en-us/articles/115012771647-Using-the-Workable-API-to-create-a-careers-page) | Публичный account feed; для SPI bearer с `r_jobs`; A/B/D | `www.workable.com/api/accounts/{tenant}?details=true`; SPI `{tenant}.workable.com/spi/v3/jobs?state=published` | Для SPI `limit`, `since_id`, `max_id` |
| [Recruitee](https://docs.recruitee.com/reference/offers) | Token Careers API; B/D | `{tenant}.recruitee.com/api/offers/`, деталь `/api/offers/{id}` | Для Careers list не подтверждена |
| [BambooHR](https://documentation.bamboohr.com/reference/get-job-summaries) | Разрешённый ATS API, не анонимный feed; D | `{tenant}.bamboohr.com/api/v1/applicant_tracking/jobs` | Не подтверждена |
| [Teamtailor](https://docs.teamtailor.com/) | Token public-read и версия API; B/D, C отдельно | `api.teamtailor.com/v1/jobs`, NA: `api.na.teamtailor.com` | JSON:API `links.next`, `page[size]` |
| [Personio](https://developer.personio.de/docs/retrieving-open-job-positions) | Включаемый работодателем XML без credentials; A/B/D | `https://{tenant}.jobs.personio.de/xml` или `.com/xml` | Не описана |

### Поля, ссылка для отклика, актуальность

| ATS | Стабильный ID и данные | Ссылка и жизненный цикл |
| --- | --- | --- |
| Greenhouse | Posting `id`, не `internal_job_id`; `content=true`, место, отдел, `updated_at`; опциональная зарплата в деталях | `absolute_url`; полный список доски, но tombstone нет; проверять deadline и повторное отсутствие |
| Lever | Posting `id`, категории, места, описание, опциональная зарплата/формат | `applyUrl`, отдельно `hostedUrl`; после всех страниц отсутствие требует повторного наблюдения; публичная дата публикации не гарантирована |
| Workday | Контракт разрешённого feed, ID и поля пока не установлены | Только разрешённый URL работодателя; нельзя делать API из HTML |
| Ashby | Публичный отдельный ID не документирован; партнёрский feed даёт UUID | `applyUrl`/`jobUrl`; `isListed=false` исключается, до кода подтвердить идентичность |
| SmartRecruiters | `id`/UUID, компания, место, детали `jobAd.sections`, `releasedDate` | `applyUrl`; `active=false` скрывает, отсутствие — после полного повторного списка |
| Workable | SPI `id`/shortcode, состояние, место, зарплата; равенство публичному feed не доказано | `application_url`/`url`; показывать только published |
| Recruitee | ID/зарплата/даты/URL требуют проверенной фикстуры ответа | Hosted offer; отсутствие использовать только после проверки полного списка с token |
| BambooHR | Summary не доказывает публичность или полный текст | Нужен отдельный разрешённый канал; статусы ATS сами по себе не достаточны |
| Teamtailor | JSON:API ID, отдел/место, зарплата, статус, даты | Карьерная ссылка; только публичные страницы и разрешённые поля |
| Personio | Position `id`, отдел/офис, XML-описание, занятость | Ссылка на `/job/{id}` на том же хосте; XML открытых позиций без отдельного сигнала архива |

Полный список не обязательно атомарный снимок. Отсутствие означает
«не показана сейчас», а не «должность закрыта». Неизвестное поле
остаётся nullable; зарплату из вопросов анкеты нельзя переносить в вакансию.

## 3. Особенности и лимиты провайдеров

- **Greenhouse.** Один запрос списка может содержать описание. Числовой ID
  сохраняется как десятичная строка без float64. Prospect posts нужно
  отличать от вакансий. Числовая квота публичного GET не найдена.
  [Данные зарплаты](https://support.greenhouse.io/hc/en-us/articles/10028084062491-Add-pay-transparency-to-a-job-post)
  опциональны; дополнительные запросы учитываются в бюджете.
  [MSA §4(d)](https://www.greenhouse.com/master-subscription-agreement)
  содержит ограничения договора и fair use; лимиты Harvest нельзя
  приписывать Job Board.
- **Lever.** Глобальный и EU хосты различны. Квота GET в
  [публичном Postings API](https://github.com/lever/postings-api) не найдена;
  лимит application POST к нему не относится. Собирайте все разделы
  описания. [Changelog Data API](https://hire.lever.co/developer/updates)
  описывает удалённые публикации для *авторизованного* API, не для
  анонимного Postings API.
- **Workday.** [Integration Cloud](https://www.workday.com/content/dam/web/en-us/documents/datasheets/workday-integration-cloud-connectors-hcml-datasheet.pdf)
  описывает экспорт активных вакансий. Наличие CXS-маршрутов в сторонних
  коллекторах не подтверждает официальный анонимный контракт, ID,
  пагинацию и статусы. [Условия](https://www.workday.com/en-us/legal/site-terms.html)
  требуют отдельного разрешения на API. Обход браузерной защиты не предлагается.
- **Ashby.** `isListed=false` нельзя публиковать. Публичная схема не
  гарантирует отдельный ID, поэтому нельзя заменять его хешем названия.
  [Партнёрский feed](https://developers.ashbyhq.com/docs/dedicated-partner-job-feeds)
  даёт UUID, время, почасовые JSON/XML и opt-in работодателей; права и
  условия хранения всё равно требуют соглашения.
- **SmartRecruiters.** [Руководство Posting API](https://developers.smartrecruiters.com/docs/posting-api)
  упоминает ключ/OAuth при примерах анонимного GET: уточните внешний
  доступ для tenant, не получая внутренних вакансий.
  [Лимит клиента](https://developers.smartrecruiters.com/docs/throttling-policies):
  10 запросов/с и 8 одновременных; анонимный режим уточнить.
  [Partner API](https://developers.smartrecruiters.com/docs/partners-job-board-api)
  требует ключ партнёра и отношения публикации, это не бесплатный поиск.
- **Workable.** Предпочтителен официально описанный account feed, не
  обратная разработка карьерной страницы. Публичная справка не гарантирует
  все поля SPI. [SPI jobs](https://workable.readme.io/reference/jobs)
  поддерживает фильтры обновления, но delta не заменяет первый полный
  снимок. Квота публичного feed не подтверждена.
- **Recruitee.** [Справка августа 2026](https://support.recruitee.com/en/articles/1066282-api-documentation)
  требует Careers token. По [auth-документации](https://docs.recruitee.com/reference/authentication-1)
  неавторизованные вызовы прекращаются **10 февраля 2027 года**; заголовок
  `X-Careers-Sites-Token`. Схема ответа и квота Careers требуют проверки.
- **BambooHR.** [Job summaries](https://documentation.bamboohr.com/reference/get-job-summaries)
  требует ATS-доступ и может включать непубличные состояния.
  [Условия разработчика](https://www.bamboohr.com/legal/developer-terms-of-service)
  требуют письменное разрешение клиента и approved auth; передача ключа
  клиента третьим лицам запрещена, кэш ограничен, после отзыва могут
  действовать сроки удаления до 30 дней. Изменение от
  [16 сентября 2026](https://documentation.bamboohr.com/docs/planned-changes-to-the-api)
  использует `429` с `Retry-After`, старый совет про `503` устарел.
- **Teamtailor.** «Public» означает область доступа token, не анонимность.
  Применяйте только public read и закреплённую версию API. Лимит
  [документации](https://docs.teamtailor.com/) — 50 запросов за 10 секунд.
  [Партнёрский канал](https://partner.teamtailor.com/job_boards/) даёт
  opt-in объявления, webhook удаления и XML текущего состояния трижды в
  день; это другой жизненный цикл, не polling token клиента.
- **Personio.** [FAQ XML](https://support.personio.de/hc/en-us/articles/29375445597725-Frequently-asked-questions-on-XML-job-integration)
  подтверждает включение работодателем, работу без credentials, несколько
  сайтов и рекомендацию часового обновления. Это не лицензия на
  неограниченную агрегацию и не числовая квота. Несколько юридических лиц
  могут делить feed; язык вакансии не зависит от языка UI JobHub.

## 4. Права на хранение и показ

Публичный GET и подписка работодателя на ATS **не** дают JobHub общую
лицензию на коммерческое переиздание. Неясные условия блокируют Production,
но не доказывают запрет. Основные источники условий:

| ATS | Источник и вывод для JobHub |
| --- | --- |
| [Greenhouse MSA](https://www.greenhouse.com/master-subscription-agreement) | Публичная документация GET не даёт JobHub срока хранения и права массового переиздания; нужна воля работодателя и проверка условий ATS |
| [Lever terms](https://www.lever.co/legal/terms-of-service) | Технический доступ не равен лицензии на syndication; нужны согласие работодателя и проверка платформы |
| [Workday terms](https://www.workday.com/en-us/legal/site-terms.html) | Нужны отдельный договор и разрешённая интеграция |
| [Ashby terms](https://www.ashbyhq.com/resources/terms), [partner feed](https://developers.ashbyhq.com/docs/dedicated-partner-job-feeds) | Партнёрский opt-in ближе к распространению, но retention/коммерческие условия согласуются отдельно |
| [SmartRecruiters partner API](https://developers.smartrecruiters.com/docs/partners-job-board-api) | Разрешённая партнёрская публикация, не свободное зеркало компаний |
| [Workable terms](https://www.workable.com/terms) | Карьерный сайт работодателя документирован; право JobHub на общий каталог требует подтверждения |
| [Tellent/Recruitee terms](https://recruitee.com/terms) | Careers token не даёт общей лицензии на стороннее использование |
| [BambooHR developer terms](https://www.bamboohr.com/legal/developer-terms-of-service) | Письменная авторизация клиента, approved auth, ограничения кэша и удаления |
| [Teamtailor partner docs](https://partner.teamtailor.com/job_boards/) | Только активированный партнёрский канал или согласованная интеграция клиента |
| [Personio terms](https://www.personio.com/terms/) | Несколько карьерных сайтов допустимы, но marketplace-права не доказаны |

Для каждого источника нужны точные права на поля, полный текст,
коммерческий показ, ссылки/брендинг, срок хранения и удаления. Фиксируйте
договор, версию, согласовавшего, область и контакт для отзыва. Разрешение
работодателя не отменяет ограничения ATS; партнёрство ATS не доказывает
владение всем контентом. По умолчанию
`production_permissions_confirmed=false`. Публичный URL, успешный dry-run
или чекбокс непроверенного аккаунта сами по себе этот флаг не меняют.

## 6. Минимальное расширение JobHub

На дату обзора были проверены
[`ingestion/service.go`](https://github.com/juniorqazaq/JobHub/blob/main/backend/internal/ingestion/service.go),
[`jobs/model.go`](https://github.com/juniorqazaq/JobHub/blob/main/backend/internal/jobs/model.go),
[`jobs/postgres_store.go`](https://github.com/juniorqazaq/JobHub/blob/main/backend/internal/jobs/postgres_store.go),
[`jobs.sql`](https://github.com/juniorqazaq/JobHub/blob/main/backend/sql/queries/jobs.sql) и
[`000002` миграция](https://github.com/juniorqazaq/JobHub/blob/main/backend/migrations/000002_create_vacancy_supply.up.sql).
Импорт был привязан к `RunJooble`/`jooble.Normalize`; advisory lock начинался
после сбора; `UNIQUE(source, external_id)` и защита по времени наблюдения
уже работали. Сохраните эти основы. Нейтральный `Collect` и обёртка
совместимости `RunJooble` позволяют не дублировать сохранение внутри ATS.

Проект интерфейса:

```go
type VacancyProvider interface {
    ValidateSource(SourceConfig) error
    Capabilities() Capabilities
    Collect(context.Context, SourceConfig, CollectOptions) (CollectionResult, error)
}
```

`CollectOptions`: deadline и бюджеты запросов/байтов/вакансий с учётом
HTTP. `CollectionResult`: нормализованные записи, увиденные ID (включая
распознаваемые отвергнутые), ошибки, счётчики, lifecycle, scope/version,
время, watermark и явная полнота с причиной. Адаптер отвечает за
пагинацию/маппинг, сервис — за проверку, дедупликацию, политику и
атомарную запись. Streaming добавлять только при измеренной потребности.

Новые поля модели допустимы для отдельного source/apply URL, проверенной
связи компании, lifecycle и времён провайдера. Зарплата и формат
записываются структурно только при надёжном значении. SQL/sqlc меняются
вместе после согласования. Не выдумывайте описания и даты. До записи
проверяйте HTTPS URL, ID/название, честный `full`/`snippet`, валюту,
единицы зарплаты и внешний отклик; HTML очищайте. Данные кандидатов и
вопросы анкеты не относятся к контракту вакансии.

## 7. Предложение по реестру источников

Расширяйте существующий `job_sources`, не создавайте параллельный `sources`
и не меняйте ключ уникальности вакансии. `source` — неизменный ID вроде
`greenhouse:source-<opaque-id>`; `provider` — тип адаптера, один адаптер
может обслуживать много источников.

| Поле/группа | Назначение |
| --- | --- |
| `source`, `provider`, `display_name`, `market` | Существующие поля; рынок не доказательство допуска |
| `company_id` | Только проверенная связь с одной компанией, nullable |
| `careers_url` | Человеческий канонический URL и подтверждённая идентичность доски |
| Typed config | Tenant/board token, регион/site/язык по необходимости; без дублирующих полей |
| `enabled` | Переключатель немедленного отключения, изначально false |
| `production_permissions_confirmed` | Финальный фильтр, меняется после привилегированной проверки |
| Атрибуция | Согласованный текст/ссылка без произвольного HTML |
| `refresh_interval`, `freshness_policy` | Интервал с jitter; версия политики срока, отсутствия и удаления |
| Запись о разрешении | Поля, коммерческий объём, доказательство, дата/версия, контакт для отзыва |
| Secret binding | Отдельное защищённое хранилище; ключи не в публичных строках |
| Версия конфигурации | Повторная проверка при изменении доски, scope или политики |
| Health | Вычислять из сохранённых запусков, не давать редактировать вручную |

Не храните сырые exception как свободный `last_failure`; используйте
безопасные коды и время. Не угадывайте работодателя и не добавляйте
произвольный endpoint override. Проверяйте уникальность провайдер +
канонический tenant/регион/site. Язык и KZ-фильтр не создают новые копии
вакансий. Переезд источника к другой компании — новый source, а
подтверждённое переименование сохраняет ID с проверенной правкой.

Одна компания JobHub может иметь собственные вакансии и несколько
подтверждённых feed. До проверки полномочий источник не связывается с
компанией. Для multi-company партнёрского feed нужны отдельные ID
работодателей; slug/название не доказывают юридическое владение.

Будущий процесс: настройки компании -> URL -> точное определение ATS ->
проверка контроля и прав показа -> dry-run -> ревью -> включение. Контроль
может подтверждаться разрешённым ATS admin flow, проверкой домена с
ответственным владельцем или договором, проверенным оператором. Вставленный
URL, похожий email или читаемый token недостаточны. Право владения ключом и
право показа контента — отдельные проверки. Отзыв разрешения немедленно
останавливает импорт/показ и запускает согласованное удаление.

## 8. Точное определение ATS по URL

Результат: `{provider, tenant_config, canonical_careers_url, evidence,
confidence: exact|unknown}`. Это не разрешение и не доказательство
владения. Разбирайте URL настоящим парсером и сравнивайте точные хосты,
а не подстроки вроде `evilgreenhouse.io`. Сохраняйте регистр tenant;
отклоняйте credentials, неожиданные порты и обход пути.

| Признак URL | Результат |
| --- | --- |
| `boards.greenhouse.io/{board}`, `job-boards.greenhouse.io/{board}` | Greenhouse board |
| `jobs.lever.co/{site}`, `jobs.eu.lever.co/{site}` | Lever site и регион |
| `{tenant}.wdN.myworkdayjobs.com/[locale]/{site}` | Кандидат Workday, не разрешение CXS |
| `jobs.ashbyhq.com/{board}` | Ashby board с сохранением регистра |
| `careers.smartrecruiters.com/{company}` или `jobs.smartrecruiters.com/{company}/…` | SmartRecruiters company |
| `apply.workable.com/{account}` | Кандидат Workable, подтвердить account |
| `{tenant}.recruitee.com` | Recruitee tenant |
| `{tenant}.bamboohr.com/careers/…` | BambooHR tenant, feed не подтверждён |
| `{tenant}.teamtailor.com` | Teamtailor board, API account требует конфигурации |
| `{tenant}.jobs.personio.de` или `.com` | Personio account и домен |

Для собственного домена работодателя возвращайте unknown, пока отдельно
разрешённая ограниченная проверка не найдёт прямую ATS-ссылку. Возможный
лимит — одна указанная страница и два redirect, без рекурсивного обхода,
JS и угадывания slug. Противоречивые признаки дают unknown. Пустая
корректная доска не считается ошибкой определения.

Будущие исходящие запросы должны отклонять private/loopback/link-local IP,
проверять DNS и каждый redirect, разрешать только хосты API провайдера,
ограничивать байты, время и тип содержимого. XML — без external entities.
Ключи не передаются между хостами; неизвестный регион — повод для проверки,
не обхода WAF.

## 9. Проект dry-run

Первоначально предлагалась команда `jobhub collect --source <source-id>
--dry-run --sample 5`; на дату этого исследования она **ещё не была
доступна**. Поздний Greenhouse POC реализовал её ограниченный вариант —
см. отдельный документ.

Dry-run использует тот же адаптер, проверку и дедупликацию, но не
создаёт writable store, ingestion run, health, cursor, изменение прав,
кэш или уведомления. Для зарегистрированной конфигурации предпочтительна
read-only роль БД, fixture может обходиться без БД. Живой dry-run всё ещё
расходует сетевую квоту.

Отчёт с ограниченным размером содержит источник/провайдера, фактические
HTTP-попытки (включая retry/redirect/detail), получено, нормализовано,
некорректные записи и причины, повторы `(source, external_id)`, первые N
примеров в стабильном порядке, lifecycle, полноту, достигнутые лимиты и
исход `complete`/`partial`/`failed`. Не называйте число вставок и
обновлений измеренным, если БД не менялась. Примеры скрывают ключи,
подписанные URL, данные кандидатов и сырые ошибки; важные tracking URL
сохраняются в БД, но секретные query-параметры не выводятся. Корректный
пустой полный feed — успех; частичный/ошибочный результат должен быть явным.

## 10. Состояние источника и расписание

Истина — сохранённые `ingestion_runs`. При реализации могут потребоваться
`last_attempt_at`, `last_success_at`, `last_complete_success_at`, время и
категория ошибки, число последовательных сбоев, вакансии/запросы,
некорректные записи, scope/config version и полнота. Dry-run не считается
синхронизацией.

Предлагаемый порядок health: `disabled`; `permission_blocked` при отсутствии
или отзыве прав; `failing` при повторных ошибках (начальный порог 3) либо
неверном ключе; `degraded` при одиночной ошибке/частичном результате/
просроченном запуске; `healthy` при своевременном успешном сохранении.
Первый запуск без истории обозначайте `never_synced`, а не успехом.
Корректная пустая доска может быть healthy. `401/403` — доступ, `429` —
квота, timeout/5xx — транспорт, JSON/XML — разбор, rollback — сохранение.
Не всякий `403` означает юридический отзыв разрешения; HTML-страница входа
не является пустой доской.

Расписание должно быть отдельным по источникам, с jitter и общим бюджетом
провайдера. На источник — не более одного активного поколения сбора;
lease/generation охватывает fetch до commit. Advisory lock только после
fetch не предотвращает старый снимок поверх нового. Временные ошибки
повторяются ограниченно с `Retry-After` и backoff; auth/schema ошибки не
повторяются вслепую. Метрики учитывают и неудачные попытки. Уведомления
оператору отправляются при переходе состояния, не на каждом poll.

## 11. Актуальность и повторы

Полный снимок требует всех страниц, одинаковых source/scope/config,
проверенных контейнера и ID, согласованного total, отсутствия достигнутых
лимитов и неразобранных ошибок. Опознаваемая некорректная запись считается
увиденной, но не стирает валидный текст; неидентифицируемая не допускает
сверку отсутствия. Повторы с конфликтным ID делают полноту неопределённой.
Нельзя закрывать вакансии по частично разобранному входу.

Собирайте все разрешённые ID доски, затем применяйте KZ-фильтр отображения:
смена языка/географии не должна выглядеть закрытием вакансии у источника.
Частичный поиск не даёт сигналов исчезновения. Offset-пагинация при
параллельных изменениях может пропускать записи, поэтому нужны повторные
полные наблюдения. В одной транзакции проверяйте поколение/версию,
сохраняйте валидные записи, применяйте явные статусы, сверяйте отсутствия
и завершайте запуск. Ошибка откатывает всё. Исчезновение — локальное
доказательство `removed`, не вымышленный `external_archived_at`. Повторное
появление того же ID возвращает тот же UUID и прежний `first_seen_at`.

Предварительные, **не одобренные провайдерами** интервалы:

| Источник | Предложение |
| --- | --- |
| Greenhouse | Обновление каждые 6 ч; скрытие после двух полных отсутствий с интервалом; максимум 24 ч непроверенного показа |
| Lever | Каждые 6 ч, два полных постраничных наблюдения, максимум 24 ч показа |
| Ashby public | Только `isListed`, сначала подтвердить ID; интервалы после фикстур |
| Ashby partner | Не чаще почасовой генерации по договору |
| SmartRecruiters | 6 ч после уточнения доступа; `active=false` действует сразу |
| Workable/Recruitee | Только после проверки полного published scope; delta не доказывает отсутствие |
| Teamtailor | Клиентский API по квоте; партнёрский XML не чаще трёх генераций в день |
| Personio | Ежечасное обновление по справке; предлагаем максимум 6 ч и два наблюдения |
| Workday/BambooHR | Нет Production-политики без разрешённого контракта |
| Jooble | Частичный ранжированный поиск без закрытия по отсутствию |

Соблюдайте более строгие договорные сроки удаления. Устаревание — не
подтверждённое провайдером закрытие. `304` годится только при сохранённом
проверенном снимке с теми же правами и scope. ID сохраняйте как непрозрачную
строку без округления float64, изменения значимых символов и замены
requisition ID/хешем названия. Межисточниковое сходство — диагностика, не
автоматическое объединение.

## 13. Первый и второй адаптеры

**Greenhouse:** публичный документированный GET, ID публикации, описание
в списке, время обновления/срок и пример KZ делают его небольшим первым
шагом. Анонимность GET не заменяет разрешение работодателя и условий ATS.
Отсутствующий формат или опыт остаётся неизвестным.

**Lever:** KZ-примеры, стабильные ID, явный apply URL, данные формата и
зарплаты при наличии. Пагинация и отсутствие публичных событий закрытия
слегка усложняют реализацию; брать после проверки общего слоя Greenhouse.

У SmartRecruiters сильные местные примеры, но неясность auth. Ashby
предлагает хороший партнёрский opt-in, требующий подключения. Охват
Workday не компенсирует неясный доступ. Не реализуйте десять адаптеров
одновременно; при появлении другого разрешённого KZ feed приоритет можно
пересмотреть.

## 14. Проект ограниченного Greenhouse POC на дату исследования

Тогда предлагалось выбрать две небольшие доски с разрешением работодателя
и, возможно, третью тестовую. `example` в документации — пример токена,
Wolt — указание географической релевантности, не разрешённая фикстура.
Бюджет: до **200 записей** и **12 HTTP-попыток** суммарно на dry-run и
две синхронизации, включая retry/redirect и до двух detail запросов.
Местные ограничения: не более 1 запроса/с, 1 параллельного запроса,
timeout 20 с, ответ 5 МиБ. Без пагинации большая доска отклоняется
как частичная, не обрезается молча. База — отдельная локальная,
Production-разрешение false, удалённые credentials не использовать.

Приёмка: точный ID, стабильный UUID при повторе, обновление существующей
записи, проверка удаления/возврата только на фикстуре, отсутствие ложной
свежести после ошибок, внешний `absolute_url`, скрытие неподтверждённых
источников и полный запрет записи в dry-run. Нужны тесты пустой доски и
перекрывающихся запусков. Реальную вакансию работодателя не меняют ради
теста. Бюджет не расширяется без нового разрешения.

## 15. Вопросы перед подключением источника

1. Кто у работодателя уполномочен разрешить JobHub хранение, индексацию и
   коммерческий показ полного текста? Какие юрлица, поля, логотипы,
   tracking, атрибуция, сроки и удаление входят в разрешение?
2. Покрывают ли договоры Greenhouse/Lever такой показ, каковы GET-лимиты и
   требуется ли отдельное одобрение ATS? Какие две доски допустимы для POC?
3. Для Workday: какой официальный экспорт/API и договор задают ID,
   полноту и удаление?
4. Для Ashby: есть ли ID публичной доски либо нужен партнёрский feed?
   Каковы retention, коммерческие условия и отзыв работодателя?
5. Для SmartRecruiters: внешний GET анонимен или нет, какова квота и нужен
   ли статус партнёра Job Board?
6. Для Workable/Recruitee: какие текущие схемы ответа, требования token,
   стабильность ID, полнота и лимиты?
7. Для BambooHR: какая разрешённая третьесторонняя auth и публичная схема
   полного текста/URL? Ключ клиента как обходной путь не принимать.
8. Для Teamtailor/Personio: права, дочерние компании, удаления, региональные
   хосты и частота.
9. Для каждой удалённой вакансии: принимает ли работодатель кандидатов из
   Казахстана, а не просто указывает рынок или переезд?

Этот документ не предоставляет нового API-доступа, прав Production или
разрешения запускать POC.
