# Проверка безопасности

Используйте при изменении авторизации, ключей провайдеров, резюме, откликов
или доступа к базе данных.

## Серверные ограничения

- Проверяйте владение в Go backend; скрытый элемент UI не заменяет авторизацию.
- Резюме не хранятся среди публичных файлов frontend.
- Работодатель читает отклики и резюме только для вакансий своей компании.
- Для собственных и внешних вакансий действуют разные сценарии отклика.

## Секреты

- Не выводите `.env`, API-ключи, токены сессий, пароли и реальные строки подключения.
- Ключи провайдеров остаются на сервере.
- В примерах используйте заполнители.
- Не делайте снимки экрана с содержимым резюме или учётными данными.

## Доступ к базе данных

- Не открывайте схему `jobhub` через Supabase Data API или анонимные ключи.
- Включайте RLS той же миграцией, которая создаёт таблицу.
- Добавляйте политики только для спроектированного и протестированного доступа клиента.
