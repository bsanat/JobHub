# Стратегия получения вакансий, 2026 год

**Исследование от 24 сентября 2026 года.** Оценка источников не означает
разрешение подключить их к Production. Более раннее исследование MVP 0
сохранено отдельно как исторический контекст.

## Вывод

JobHub уже поддерживал собственные вакансии и ограниченный импорт Jooble
Kazakhstan. База и API сохраняли источник, направляли отклик на внешние
вакансии к источнику, устраняли повторы внутри провайдера и скрывали
источники без подтверждённых Production-прав. Главный вопрос — законный,
актуальный поток вакансий, а не базовая механика импорта.

Следующий источник для **переговоров**, а не немедленной разработки —
**Enbek**. Нужны письменное соглашение об интеграции/распространении и
рабочий feed. [Описание портала](https://www.enbek.kz/ru/node/3205)
говорит о ежедневном обновлении из разных источников. Официальная
статистика: [1,328 млн публикаций в 2025 году](https://www.gov.kz/memleket/entities/enbek/press/news/details/1150201?lang=ru)
и [108 700 за июнь 2026](https://www.gov.kz/memleket/entities/enbek/press/news/details/1258464?lang=ru).
Это поток публикаций, не число одновременно активных или доступных для
законного импорта вакансий.

[Страница web services](https://www.enbek.kz/ru/web-services) всё ещё
указывала XML в форматах Jooble/Yandex, однако оба URL возвращали HTTP 404
на дату исследования. Открытая лицензия на хранение, публичное
распространение, коммерческий показ, атрибуцию и удаление не найдена.
Поэтому Enbek отнесён к классу **C — письменное партнёрство обязательно**.

Jooble — класс **B для ограниченного POC** и **C для Production** до
письменного уточнения прав и устойчивой квоты. Исследование не расходовало
запросы Jooble. Цель 500–1000 активных вакансий технически скромна на
фоне рынка, но обещать конкретное доступное количество нельзя до проверки
прав, feed, покрытия и свежести.

## Классы решения

- **A:** можно изучать для Production при обычной проверке прав и качества.
- **B:** только ограниченный POC; для Production не хватает прав или доступа.
- **C:** требуется письменный договор или партнёрство.
- **D:** не подходит для получения вакансий JobHub в рассматриваемом виде.

## Сравнение источников

| Источник | Официальный доступ и данные | Основные ограничения | Класс |
| --- | --- | --- | --- |
| Enbek | Портал Казахстана; названы XML feed, но URL давали 404 | Нет рабочего контракта feed и прав на повторный показ; публичная вакансия до месяца, семантика feed неизвестна | **C** |
| HeadHunter / hh.kz | `api.hh.ru`, богатые детали, работодатели, зарплаты, время; `page`/`per_page` до 100, глубина до 2000 | Стандартные условия ограничивают передачу данных третьим лицам и постоянную публичную базу; нужна отдельная лицензия | **C** |
| Jooble KZ | Региональный ключ, REST POST, ID/название/сниппет/компания/ссылка/`updated`; страницы и `totalCount` | 500 запросов за всю жизнь ключа; нет доказанного feed удаления и правил хранения/коммерческого повторного показа | **B POC / C Production** |
| Adzuna | REST-поиск с `app_id`/`app_key`, сниппет, зарплата и redirect URL | Казахстанский рынок не подтверждён; квоты 25/мин, 250/день, 1000/неделю, 2500/месяц | **D для KZ** |
| LinkedIn | Партнёрские Talent API отправляют вакансии **в** LinkedIn | Нет подходящего публичного API для чтения/переиздания; scraping запрещён | **D** |
| QSamruk | Казахстанский сайт, 1012 вакансий на дату исследования | Нет задокументированного публичного feed/API и прав повторного показа | **C** |
| Rabota.kz | Казахстанская площадка | Официальный API/feed и условия интеграции не найдены | **C** |
| Greenhouse | Публичный GET доски работодателя с полной вакансией при запросе | Для импорта нужно разрешение работодателя; общий доступ не равен лицензии агрегатора | **A с согласием работодателя / C для массового сбора** |
| Lever | Публичный per-employer Postings API, `skip`/`limit`, описание и apply URL | Для массового использования требуется разрешение/партнёрство | **A/C** |
| Workable | Публичные published endpoints, расширенный SPI по ключу | Состояния draft/published/closed/archived; права зависят от работодателя | **A/C** |
| SmartRecruiters | Per-company Posting API, партнёрский Job Board API | Для нескольких компаний нужны Partner API Key и отношения публикации | **A/C** |

## Права, показ и удаление

- **Enbek:** бесплатный доступ к порталу не означает экспортную лицензию.
  Нужно письменное описание полей, объёма, атрибуции, удаления и SLA.
- **HH:** [условия API](https://hh.ru/article/15116) ограничивают передачу
  данных, требуют актуальности и быстрого удаления архивных вакансий.
  Значок HH не заменяет право на публичную базу JobHub.
- **Jooble:** [страница API KZ](https://kz.jooble.org/api/about) допускает
  показ ответа порталами/поисковиками в своём дизайне, но точные правила
  длительного хранения, атрибуции, прав исходных издателей и удаления
  следует подтвердить отдельно. [REST-документация](https://help.jooble.org/en/support/solutions/articles/60001448238).
- **Adzuna:** [условия](https://developer.adzuna.com/docs/terms_of_service)
  разрешают публикацию объявлений при соблюдении требований, включая
  связанную атрибуцию «Jobs by Adzuna» минимум 116 x 23 px. После
  прекращения использования данные удаляются со страниц. Нет доказанного KZ.
- **LinkedIn:** [API публикации](https://learn.microsoft.com/en-us/linkedin/talent/job-postings/job-posting-overview?view=li-lts-2026-03)
  предназначен для отправки вакансий в LinkedIn, не для их извлечения;
  [условия](https://www.linkedin.com/legal/user-agreement) ограничивают
  копирование и распространение.
- **QSamruk/Rabota.kz:** нужен прямой контакт и письменный контракт feed.
- **ATS работодателей:** общедоступный endpoint рассчитан прежде всего на
  сайт самого работодателя. JobHub нужен его договор или партнёрская
  программа ATS; скрытие/удаление следует согласованному жизненному циклу.

## Проверенные официальные материалы

### Enbek

[Описание портала](https://www.enbek.kz/ru/node/3205) и
[страница feed](https://www.enbek.kz/ru/web-services) показывают намерение
машинной выдачи. Ссылки [Jooble XML](https://www.enbek.kz/ru/xml/jooble) и
[Yandex XML](https://www.enbek.kz/ru/xml/yandex) возвращали 404.
[FAQ](https://www.enbek.kz/ru/faq) говорит о публикации до месяца и
последующем архиве работодателя, но не доказывает такую же семантику feed.
Не найдены действующая схема, способ авторизации, квота, открытая лицензия,
обязательная атрибуция и SLA удаления. Рыночная статистика выше не даёт
прогноз числа активных импортируемых вакансий.

### HeadHunter

[OpenAPI](https://api.hh.ru/openapi/en/redoc) содержит богатый поиск и
детали. Блокирует не техника, а стандартные права: постоянная публичная
копия вакансий для JobHub требует отдельного письменного разрешения на
хранение, показ, работодателей, кэш и удаление.

### Jooble

[API KZ](https://kz.jooble.org/api/about) описывает региональный ключ.
[Инструкция подключения](https://help.jooble.org/en/support/solutions/articles/60000922689-how-to-connect-to-the-jooble-rest-api)
размещает ключ в URL — такие URL нельзя логировать. Нет документированного
detail/delete endpoint; в выдаче только `updated`, без даты публикации и
закрытия. Локальный срок свежести 72 часа — политика POC, не гарантия
провайдера. Production permissions должны оставаться выключенными до
подтверждения условий.

### Adzuna и LinkedIn

[Поиск Adzuna](https://developer.adzuna.com/docs/search) возвращает
страницы и сниппет, но KZ-рынок не был подтверждён. У LinkedIn проверен
партнёрский поток отправки работодателем, а не общий feed чтения.

### Сайты Казахстана и ATS

[QSamruk](https://qsamruk.kz/) показывал 1012 вакансий, но HTML-страница не
заменяет разрешённый feed. Для Greenhouse есть
[Job Board API](https://docs.greenhouse.io/job-board.html), для Lever —
[Postings API](https://github.com/lever/postings-api), для Workable —
[инструкция careers API](https://help.workable.com/hc/en-us/articles/115012771647-Using-the-Workable-API-to-create-a-careers-page),
для SmartRecruiters — [Posting API](https://developers.smartrecruiters.com/docs/endpoints)
и [партнёрский Job Board API](https://developers.smartrecruiters.com/docs/partners-job-board-api).
Публичный endpoint не даёт безусловное право на массовый импорт.

## Запрос к Enbek перед реализацией

Нужны письменные ответы: действующий endpoint вместо XML URL и тестовый
feed; полный снимок или delta; обновление/архив/удаление; право хранить и
публично показывать название, описание, компанию, зарплату и место;
включение сторонних вакансий и их downstream-права; атрибуция/логотип/
обратная ссылка; срок хранения и SLA удаления; коммерческое использование,
договор и цена; авторизация, квота, частота и IP-правила; стабильные ID
вакансии/компании; требование внешнего отклика.

Только после рабочего feed и письменного разрешения возможен ограниченный
POC **до 10 запросов**: один на схему, до трёх страниц узкой области,
один повтор для ID/идемпотентности, один контролируемый update/removal и
четыре на документированные повторы/пагинацию. Без HTML scraping. Не
больше 100 записей в изолированной базе, только внешние ссылки и безопасные
счётчики без ключей.

Продолжать можно лишь при совпадении письменных прав с моделью JobHub,
стабильных ID и схемы, надёжном правиле закрытия/полного снимка, достаточной
квоте и пригодных полях. Остановиться, если нельзя хранить/показывать,
feed не отражает жизненный цикл, ключ должен попасть в браузер или
частота обновлений оставит устаревшие вакансии публичными.
